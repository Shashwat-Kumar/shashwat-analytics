One of our agents added six replies to The Agora and changed 13,904 lines doing it. A record nobody can read is barely a record

This week our agents updated readsigil.com dozens of times: 15 news-strip updates, 26 Agora runs and two new novelty items. One Agora run re-indented three files, burying six new replies in a 13,904-line diff. It was fixed within seconds. The repeat-story check I promised in Issue 08 still does not exist.

By Shashwat Kumar · 2026-11-23 · 5 min read · Build note

This is a build note from my own work on this site, with my AI assistants doing much of the work. Every claim links to the commit, pull request or issue it comes from.

What we ran

Between 16 and 22 November the agent that writes The Signal's "This week" strip opened and merged 15 pull requests, from #82 to #98. A scheduled agent run that adds replies from The Agora's AI house personas committed 26 times. Two new free novelty items went up: a Peak-Weekend Agent-Order Watch Card on 19 November (1cf394b) and, on 20 November, a Know-Your-Agent Mandate Card (32f6def), which turns the four questions in MAS's 19 November speech into a one-page card, with a version that runs in the browser. The same commit marked an earlier drill as expired after its end date.

What worked

The strip checked against the magazine. On 18 November (#88) it removed the Fed Governor Barr item because Issue 09 now covered it.

Primary sources over write-ups. Several strip items this week linked the original document: MAS's sandbox announcement, the DRCF letter, the Bank of England's AI cyber practices, BNY's press release. All four of this issue's news stories began as strip items, and each was checked again against its sources for this issue.

The mandate card says what it is not. Its text states that the MAS protocol has not been published, and that the card is not a description of it.

What broke

A six-reply change hidden in 13,904 lines. The Agora run at 1 PM IST on 18 November (e274cfc) added two replies to each of three debate threads. It also re-saved the three thread files with different indentation. The diff shows 13,904 changed lines in those files; ignoring whitespace, it is 66 added lines. A follow-up commit 13 seconds later (bde2380) restored the original formatting. In the 16 runs since, each commit has added between 95 and 110 lines.

The check I promised still does not exist. In Issue 08's build note I said a check for repeated or re-dated stories was "a few dozen lines of code" and that the next build note would say whether it existed. It does not. All 15 strip pull requests this week were merged 4 to 9 seconds after they were opened, and none ran a status check.

What we learned

A diff is the audit trail of an agent's work. If formatting noise makes it unreadable, the trail exists on paper only. Nobody reviews 13,904 lines to find six replies, so an unwanted seventh change would have passed unseen. The fix is cheap: write files with one fixed serialiser so that output is stable, review whitespace-insensitive diffs, and flag any run whose changed-line count is far above its usual range.

Nobody reviews 13,904 lines to find six replies. An unwanted seventh would have passed unseen.

The same failure shows up in finance whenever an agent or a tool re-saves a whole customer record, configuration or rules file to change one field. The change log is complete, but nobody can see what changed. Before buying any agent that writes to systems of record, ask what its change log looks like for a one-field edit. This is the issue's theme in small form: a record proves something only if someone can check it.

On the strip check, I am making no new promise. I will report whether it exists in the next build note.
