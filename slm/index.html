01 / THE BASICS

What is an SLM, exactly?

A small language model is a language model with comparatively few parameters. There is no universal parameter cut-off. It still predicts tokens; being small doesn't make it rule-based, deterministic or immune to hallucination.

PROMPT

Tell it what to do.

Instructions and examples improve behaviour without changing model weights. Try this first; it may be enough.

RETRIEVE

Give it what it needs.

RAG supplies relevant information at request time. Better for current documents and changing policies than memorising facts in weights.

FINE-TUNE

Teach a repeatable behaviour.

Adapt weights using labelled examples. Most practical 'build an SLM' exercises start from an existing model, not random initialisation.

02 / MYTHBUSTERS

Six claims worth interrogating.

Open each claim before you make a technology decision. The answer is usually more interesting than yes or no.

01 A smaller model is always cheaper. +

False. Weight size helps, but total cost depends on hardware, utilization, throughput, prompt length, support, monitoring and rework. Benchmark cost per successful task on your own workload.

02 Small models are automatically private. +

False. Local deployment can keep inference data within your boundary. Privacy still depends on logging, access controls, data handling, hosting, retention and training-data rights.

03 Fine-tuning uploads all company knowledge. +

Wrong tool. Fine-tuning is useful for output format, style or a narrow task. For changing reference facts, use retrieval, a database or governed tools. Training is not a reliable knowledge store.

04 An SLM never hallucinates on a narrow task. +

False. It can invent labels, mishandle ambiguity or fail on unfamiliar language. Constrain outputs, validate them and let the system abstain or escalate.

05 Quantization and fine-tuning are the same. +

No. Quantization changes how numerical weights are represented to reduce memory. Fine-tuning updates learned parameters. LoRA trains small adapter weights; it is not a quantization method.

06 More training data always fixes a bad model. +

Not necessarily. Labels, representativeness, duplicates, data leakage and task definition matter. A simple classifier or deterministic rules can outperform a generative SLM on a narrow categorisation problem.

03 / WHERE IT FITS

Give it work it can do. Keep the boundaries explicit.

✓ Reasonable starting points

  • Route incoming tickets into known categories
  • Extract fields from standardised, low-risk text
  • Tag documents for human review
  • Summarise short, well-defined content with verification
  • Private/on-device inference when the whole deployment is governed

× Not a shortcut for

  • Guaranteeing factual or legal correctness
  • Keeping rapidly changing knowledge current
  • Making credit or fraud decisions without controls
  • Handling every language or edge case out of the box
  • Eliminating the need for human review, audits or monitoring

The real decision is rules vs traditional ML vs prompted model vs retrieval vs fine-tuned model. Choose using task-level accuracy, latency, operating cost, privacy and risk—not model size alone.

04 / TRAIN

Fine-tune a model, not a slide.

LoRA freezes the foundation weights and trains a small adapter. You can adjust rank and training epochs; the script will report trainable parameters and save the adapter.

In a terminal, from the slm directory:

python -m pip install -r requirements.txt
python train.py --train data/train.jsonl --eval data/eval.jsonl --epochs 3 --rank 8

05 / THE DECISION

When should you build one?

Start only when the workflow is narrow, frequent, measurable and stable. If an SLM can't beat a cheaper baseline on the metrics that matter, don't deploy it just because the model is fashionable.

REPEATABLE

Clear input, clear output.

Can reviewers agree on the correct answer consistently?

MEASURABLE

Known failure costs.

Do you have held-out examples and an explicit threshold for intervention?

OPERABLE

Governed end to end.

Can you monitor quality, protect data and roll back safely?
